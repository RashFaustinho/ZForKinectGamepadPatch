# Validation methods and limits

Four evidence levels are kept separate:

1. **Emitted instruction checks:** hashes, original instruction signatures, branch ranges, padding, and generated byte layout.
2. **PowerPC CPU execution:** emitted adapters and selected original consumers execute in Unicorn. Narrow ABI, resource lookup or leaf-render callbacks can be fixtures; this is not complete Xbox emulation.
3. **Native Xenia observations:** real pad events, read-only state/HP/Ki/widget data, and original save writes. An input accepted by a detector is not necessarily a battle response.
4. **Rendered gameplay and saved progression:** screenshots/geometry/readback are needed for visible effects; native chapter state and a valid written save are needed for persistent progression.

The final patch passes fifteen suites: bridge, step/guard, charge start, combat feedback, action values, contextual consumers, feedback, boss prompts, HD prompts, static prompts, authored arm motion, Super defense, Super timing, content, and launch-guard priority. [Final records](../experiments/gamepad-final-v1.0.0/suite-results.json) pin all results to the final TOML digest. The exact public startup hooks/payloads were read back in Xenia, and all thirteen native 128×128 controller resources matched the authored BC3 data byte-for-byte.

The final B-priority regression executes both original choice dispatchers across 36 native selection cases, 16 unrelated-caller cases, and 16 helper ABI/no-write cases. Eight old B-plus-stick cases reproduce the original unwanted lateral priority. In the requested Super Saiyan Bardock / Full Power Frieza Score Attack match, pure B was accepted at caller `8220E8B8`, frame 10698, with the guard selection latched. The helper changes mixed-input priority; the one-off user incident cannot be attributed with certainty from that report alone.

Earlier runtime confirmations include a real player projectile after fixing non-finite hand coordinates; held lateral escape gauges reaching 1.0; actual four-choice and two-choice widgets; native Great Ape progression saved with the global unlock hook removed; visible first-person arms; three Super-defense responses; twelve card scans with valid saves; and a persistent native power-up reset. Topic notes state the precise revision, setup and limitations.

The environment used virtual-pad events and read-only guest inspection. It did not force battle HP, Ki, native QTE increments, timers, animation state, phases, results or victories. Diagnostic counters are in checked writable padding. The final release excludes all locally injected wrappers/counters and the Super tutorial lesson-selection shortcut.

Limitations remain: no exhaustive full-campaign or all-character/all-Super playthrough; no Windows/D3D12 or physical-controller verification; not every card's combat effect measured individually; numeric finiteness alone does not certify visual correctness; a favorable defense depends on the original valid/invalid choice rules. The archived front-escape attempt that stopped near 0.564 is not described as completed merely because its CPU accumulation test passes.
